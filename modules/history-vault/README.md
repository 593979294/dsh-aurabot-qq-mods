# 跨会话历史库（history-vault）

跨 DSH 会话保留聊天细节的三层存储模块。解决两个问题：

1. **会话归档后细节丢失**：主线记忆整理出「当日梗概」后会删掉当天聊天流水；DSH 会话归档后只剩最近 20 条补看。再早说过什么就没了。
2. **重复压缩上下文**：同一批内容每次整理都重新花模型调用。

## 做什么

用一份独立的 SQLite 库（`api.dataDir()/vault.sqlite`，与主记忆库互不干扰）做三层归档：

| 层 | 表 | 内容 | 来源 |
| --- | --- | --- | --- |
| L0 原文层 | `vault_lines` | 每一条收/发的消息原文 | 入站 `activity`；出站 `send`（见下） |
| L1 日摘要层 | `vault_days` | 一个聊天一天一条摘要（≤300 字） | 模型压缩 L0，每天最多 `dailyCalls` 次 |
| L2 月印象层 | `vault_months` | 一个聊天一月一条印象（≤200 字） | 模型压缩 L1 |

**L0 为什么用两个通道**：宿主只有一个 `activity out` 广播点（在 `deliverTurn` 末尾），它只覆盖「她正常回复这一轮」。私聊里大量内容走别的出口——命令回复、发图 / 发文件 / 语音文件、模块代发（`api.send` 系列）、主动搭话、桌宠转述——它们都在 `sendSegments` 直发，不经过 `deliverTurn`，也就**不会**广播 `activity`。只靠 `activity`（0.1.x 的做法）会把她说的话漏掉一半。

现在分工明确、互不重叠：

- **入站** 走 `activity`（`kind='in'`）。也收 `kind='silent'`——她看见了但决定不搭理的消息，宿主在 `activity 'in'` 之前就 return 了，只有 `silent` 带得出来。
- **出站** 走 `send` 钩子（`API.md` 写明它是「最终发给 QQ 的消息段」「所有发出去的消息都经过这里」）。`activity` 里的 `kind='out'` 直接跳过，避免同一句话说两遍。

**压缩幂等**：每层存输入内容的 sha256 指纹（`digest` 列）。指纹没变就跳过 —— 同一批内容无论整理多少次、会话压缩多少遍，都只花一次模型调用。摘要为空也会记 `-empty-` 标记，不会永远重试。每日调用数记在 `vault_meta`，模块重载不丢。

## 分层读取（skills 式 progressive disclosure）

1. **目录（自动注入，零模型调用）**：每轮聊天前塞一小段「最近摘要过的日子」备忘（`prompt` 事件）。内容落盘后不变，不反复打爆提示词缓存。
2. **翻目录（工具）**：她需要细节时用 `recall_history` 按日期或关键词查日摘要。
3. **读原文（工具）**：日摘要不够再拉当天原文片段（最多 200 条）。

## 怎么用

- 装好后自动归档、自动整理，无需配置。
- 她自己会按备忘和规则用 `recall_history`；主人可用 `/史库 [日期|关键词]` 查，`/史库` 看统计。
- 面板「已安装」页展开本模块：有独立标签页，含统计刷新、手动压缩一次、按聊天查看与清空（自定义面板）；下面是常规设置表单（启用、保留天数、压缩节奏、每日调用上限等）。

## 会访问哪些网址

不访问任何网址。全部数据只落在本机 `api.dataDir()`。

能力声明：`plugin-internals`（面板接口用了 `api.core.http` 的小工具读写请求）；文件写入全部经 `node:sqlite` 落在数据目录，不碰别的路径。

## 设置

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 启用 | 开 | 关掉后不归档不注入 |\n| 记录群聊 | 开 | 关掉后只录私聊，群不再归档（防群消息撑爆库） |\n| 群白名单 | 空 | 只录列出的群号，逗号/换行分隔；空 = 群全录 |\n| 私聊白名单 | 空 | 只录列出的 QQ 号；空 = 私聊全录。两个名单各自独立、互不越界 |
| 原文保留天数 | 0（永久） | 细节层是救命用的，建议永久 |
| 满几天压日摘要 | 1 | 只压已结束的日子 |
| 满几天压月印象 | 32 | 上个月的日摘要齐了才压 |
| 每天压缩调用上限 | 6 | 模型调用成本闸 |
| 备忘覆盖天数 | 3 | 注入备忘带最近几天的摘要 |

## 已知边界

- 群聊原文按 `MAX_LINES_PER_DAY`（400 条/聊天/天）封顶，超出丢最旧的，摘要永远压封顶时刻的输入。
- 图片 / 语音 / 文件在库里是占位符（`[图片]` `[语音]` `[文件]` `[表情]`），不存二进制内容。
- 隐私：历史库按 `chatId` 隔离，工具只能查当前聊天的历史，不能跨聊天读别人的私聊。
- **她不理的群聊消息不会进库（私聊不受影响）**。宿主的 `activity` 广播点都在「这条要交给她处理」之后：
  群里判「不回」、被 `/闭嘴` 静音、不在群白名单的消息，宿主在广播之前就 return 了，模块拿不到
  （这是插件主线的事件契约，不是本模块能补的）。想在群里留档，就把那个群加进群白名单并放开「记录群聊」。
  **私聊是全额归档的**：主人发来的每条都进（含被静音的），她说出去的每条也都进——不管走的是正常回复、
  命令回复、发图、模块代发还是主动搭话，因为出站统一从 `send` 钩子收。
- `send` 钩子收到的是一条消息的 OneBot 消息段，不是「一轮完整回复」：她一轮拆成 3 条就记 3 行。
  这也和 `activity` 的口径一致（那个按轮记），所以两种入口的行粒度不同；同一句话不会被记两遍。
- 今天这一整天的聊天不会被压成日摘要（设计如此：一天没聊完，压出来的摘要还会变，白花一次模型调用）。
  压的是「昨天及更早」，所以当天新聊的内容只存在于 L0 原文 + 工具的按天查询，第二天夜里才出现在备忘里。

## 更新记录

- **0.1.2**：修三处「记忆没真正存进来」的问题——① 出站正文在 `reply` 字段，旧代码只读 `text`，
  她说的每一句都被丢掉（实测 47 条聊天流水只进库 9 条）；② 压缩截止日判断用 `day < cutoff`，
  「满 1 天」实际要等 2 天，日摘要层从未落过盘（`days` 恒为 0）；③ 昵称是 `-` 时库里记成「-：……」，
  主人的消息改记「主人」、她的话记「她」。
  **另外把出站通道从 `activity` 换成 `send`**：`activity out` 只在正常回复时广播，命令回复 / 发图 /
  模块代发 / 主动搭话全都不经过它，私聊的出站会漏掉一半（实测 28 条出站 0 条入库）。
  现在入站走 `activity`、出站走 `send`，两边不重叠。
